# CLAUDE.md — RavonRoad

Язык документации и общения — русский. Идентификаторы, имена файлов, ветки и сообщения
коммитов — английский.

## Продукт

Операционный инструмент бригады волонтёров, которые сами ремонтируют ямы в Ташкенте.
Государственный орган вне контура: петля замкнута внутри системы.

Поток:

1. Житель заполняет форму на сайте: 1–3 фото, пин на карте, ориентир, необязательный контакт.
2. Заявка сохраняется в БД.
3. Telegram-бот отправляет карточку в группу волонтёров с inline-кнопками.
4. Модератор меняет статус кнопкой.
5. Бригада едет по координатам и чинит.
6. Волонтёр отправляет боту фото «после» и необязательную ссылку на Instagram.
7. Счётчик отремонтированного на сайте растёт.

Цель кампании — **10 000 отремонтированных ям**.

Статусы заявки: `NEW`, `ACCEPTED`, `IN_PROGRESS`, `DONE`, `REJECTED`, `DUPLICATE`,
`OUT_OF_SCOPE`. Термины — в `docs/domain/glossary.md`; термина нет в глоссарии — сначала
добавь его туда.

## Стек

Зафиксирован. Альтернативы не предлагаются, замены не обсуждаются по ходу задачи.

| Слой | Решение |
| --- | --- |
| Frontend | React 19, Vite, TypeScript, TanStack Router, TanStack Query, Tailwind |
| Backend | NestJS, модульный монолит — один сервис; Telegram-бот это модуль внутри него |
| БД | PostgreSQL + PostGIS, Prisma |
| Фото | Cloupard S3 (внешнее S3-совместимое). MinIO не используется ни в одной среде |
| Карты | MapLibre GL v5 + собственный PMTiles-экстракт в бакете (ADR-0008). Геокодер не используется |
| Локали | uz-латиница по умолчанию, ru вторая. Обе с префиксом в URL: `/uz/...`, `/ru/...` |
| CI/CD | GitHub Actions, публичный репозиторий, образы в GHCR. GitLab не используется |

Среды: **prod** — Contabo Cloud VPS 4 (4 vCPU, 8 ГБ RAM, 100 ГБ SSD), регион
European Union; **dev** — GCE e2-micro,
1 ГБ RAM, us-central1, Always Free. Обе поднимаются одним и тем же docker-compose.
Память — жёсткое ограничение: 1 ГБ на dev означает, что тяжёлые процессы в контейнерах
не запускаются. Лимиты контейнеров на проде вслед за памятью машины не подняты: они
выведены из нагрузки, а не из размера машины (SRS §12.1).

### Чего в системе нет

- Авторизации на сайте: ни JWT, ни OTP, ни таблицы `User`. Модератор идентифицируется
  `telegram_user_id` из allowlist в таблице `moderator`; `TELEGRAM_MODERATOR_IDS` —
  только источник первичного засева этой таблицы (ADR-0005).
- OpenAPI. API-контракт живёт в `packages/shared-types` и импортируется обеими сторонами
  напрямую. Генераторов клиента нет.

## Команды

Пакетный менеджер — **pnpm** (workspaces). Node ≥ 22.13.

| Команда | Что делает |
| --- | --- |
| `pnpm install` | Установка; собирает `packages/shared-types` — но **не всегда**, см. ниже |
| `pnpm dev` | Поднимает web и api параллельно |
| `pnpm build` | Сборка всех пакетов в порядке зависимостей |
| `pnpm lint` | ESLint по всем пакетам |
| `pnpm typecheck` | `tsc --noEmit` по всем пакетам |
| `pnpm test` | Vitest по всем пакетам, где есть тесты |

**`tsc` ругается на `@ravonroad/shared-types` — «has no exported member»?** Проблема не в коде,
который ты пишешь: при готовом lock-файле `pnpm install` не запускает `prepare`, и `dist`
пакета остаётся от прошлой сборки. Лечится `pnpm --filter @ravonroad/shared-types build`.
Ошибка выглядит как отсутствующий тип в чужом пакете и стоит получаса на поиски не там.
Веб-приложение этого не видит: у него алиас на исходники, а `apps/api` собирается против `dist`.

**`pnpm test` красный на четырёх тестах `outbox.spec.ts`, а CI зелёный?** Проверь миграции
локальной базы: `pnpm --filter @ravonroad/api exec prisma migrate status`. Интеграционные
тесты в CI поднимают базу Testcontainers'ом и накатывают миграции сами, а локально идут
в базу из `DATABASE_URL` — ту, что осталась с прошлой недели. Непринятая миграция даёт
не ошибку схемы, а осмысленные с виду расхождения: `expected +0 to be 2`, `expected null
not to be null`. Лечится `prisma migrate deploy`; `migrate reset` и `db push` запрещены.

Тестовый раннер — **Vitest**. Тест лежит рядом с кодом, который проверяет:
`number.ts` → `number.test.ts`. Отдельного каталога тестов нет.

Точечно: `pnpm --filter @ravonroad/api <script>`, `pnpm --filter @ravonroad/web <script>`.

Новые зависимости не добавляются по своему усмотрению. Нужна зависимость — остановись
и спроси.

## Дизайн

Источник истины по интерфейсу — снимок из Claude Design в каталоге **`design/`**: правила
системы в `design/readme.md`, foundations, 11 компонентов и экраны в `.dc.html`. Файлы
открываются в браузере как обычные страницы — сверка идёт ими, а не по описанию.

Принято направление **C** («плакатное»). `Home A` и `Home B` лежат рядом как **отклонённые**
и реализации не подлежат; `Главная.dc.html` и `Заявка.dc.html` — итерация до смены ключа.

Четыре места макета намеренно не воспроизведены — данных под ними нет, и нарисовать их
значило бы напечатать выдуманное:

- вкладка **Sputnik** — спутниковых тайлов не существует: экстракт векторный, а платного
  провайдера кампания не берёт (ADR-0008);
- **номер бригады** («brigada 4») — такой сущности нет ни в схеме, ни в контракте;
- **адрес** в подписях — геокодера в системе нет, место называет ориентир жителя (ADR-0004);
- колонка **Ovoz** в таблице списка — голосования нет ни в схеме, ни в контракте;
- колонка **Muddat** — плановых сроков система не знает; печатается случившаяся дата:
  `doneAt` у закрытой заявки, `createdAt` у остальных;
- поиск **«Manzil yoki ariza raqami»** над таблицей — эндпоинта поиска нет, публичное API
  знает только фильтры и курсор (SRS §4.3);
- **число «412 ta ariza roʻyxatda»** печатается не всегда: `ReportListResponse.total` —
  всегда `null` (COUNT(*) по фильтру = полный скан), а разбивка `/api/stats` отвечает
  только по одной оси. Пересечение «статус И район», категория и даты дают «показано N»
  по загруженным строкам (`features/stats/listTotal.ts`).

Пара **Oldin / Keyin** под недельной строкой — не отказ: она принадлежит последней
закрытой заявке, а не выборке за неделю, и рисуется, когда у той есть оба снимка
(`features/stats/latest.ts`). На сиде без фотографий блок пуст по правилу, а не по ошибке.

Появятся данные — вернуть эти места дешевле, чем вычищать выдуманные числа с публичного
сайта кампании.

Гарнитура — **Inter**, локальная, одна на весь интерфейс, моноширинной нет. Archivo из
макета не подошла: в ней нет ни кириллицы, ни U+02BB, то есть каждое `Oʻ` и `Gʻ` уезжает
в подстановку. Меняешь гарнитуру — сначала докажи покрытие `scripts/check-font-glyphs.mjs`
(разбор cmap скачанных woff2), а не объявленным `unicode-range`: у IBM Plex Mono диапазон
`U+2000-206F` был объявлен при отсутствующем глифе тонкого пробела.

## Процесс

**Каждая фича начинается со спецификации.** Порядок жёсткий:

`/specify` → `specs/NNN-slug/spec.md` → `/plan` → `plan.md` → `/tasks` → `tasks.md`
→ `/implement` по одной задаче.

Код без `spec.md` не пишется. Номер среза `NNN` — три цифры, сквозная нумерация.
Срез — это законченная ценность, доведённая от формы на сайте до реакции бота,
а не слой архитектуры.

Архитектурное решение (схема БД, границы модулей, внешняя зависимость, протокол
интеграции) фиксируется ADR в `docs/adr/` в том же изменении, что и код.

## Ветки

- `main` — прод. `dev` — интеграционная. **Прямой push в `main` и `dev` запрещён.**
  Force-push в них запрещён тем более.
- Ветка фичи создаётся от `dev` **до первого коммита**: `git checkout -b feat/NNN-slug dev`.
- Префиксы: `feat/`, `fix/`, `docs/`, `chore/`. После префикса — номер и slug среза.
- Изменения попадают в `dev` только через Pull Request.

## Правила кода

- TypeScript строгий. `any` не используется: нужен тип — опиши `interface` или `type`.
- Контракт между фронтом и бэком объявляется один раз в `packages/shared-types`
  и импортируется обеими сторонами. Дублирование типов на стороне — ошибка ревью.
- Ничего «на будущее»: ни абстракций под одну реализацию, ни заготовок папок,
  ни TODO-заглушек. Понадобится — тогда и напишем.
- Проверка перед тем, как считать работу сделанной: `pnpm typecheck`, `pnpm lint`
  и `pnpm test` — те же три команды, что гоняет CI. Не прошло — чинится, а не объясняется.
- Браузерные API защищённого контекста (`crypto.randomUUID`, `navigator.geolocation`,
  Service Worker) на dev-стенде недоступны: он открыт по http на IP-адресе, а secure
  context — это https или localhost. `crypto.randomUUID` там не просто пустой, его
  вызов бросает `TypeError` и уносит всю страницу в error boundary. Для uuid есть
  `shared/lib/uuid.ts`; для любого другого такого API нужен запасной путь или явная
  деградация. Проверка на localhost этот класс дефектов не ловит **никогда**.
- Документ противоречит коду — верь коду, потом почини документ в этом же изменении.
