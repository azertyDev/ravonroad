Срез: $ARGUMENTS

Прочитай `specs/$ARGUMENTS/plan.md` и создай рядом `tasks.md`.

## Что такое атомарная задача

- Один результат, который можно проверить, не сделав ничего сверху.
- Помещается в один коммит.
- Формулировка начинается с глагола и называет конкретные файлы или модули.
- «Сделать бэкенд» — не задача. «Добавить таблицу requests и миграцию» — задача.

## Формат tasks.md

~~~markdown
# NNN — Задачи

- [ ] T001 Название задачи
      Файлы: apps/api/src/...
      Готово когда: проверяемое условие
- [ ] T002 [P] Название задачи
      Файлы: apps/web/src/...
      Готово когда: проверяемое условие
~~~

## Правила

- `[P]` ставится, только если задача не пересекается с другими по файлам и не ждёт их
  результата. Две задачи, правящие один файл, параллельными не являются.
- Порядок: контракт в `packages/shared-types` → схема БД → API → бот → frontend.
  Всё, что зависит от контракта, идёт после него и `[P]` не получает.
- «Готово когда» — наблюдаемое условие: запрос отвечает, кнопка меняет статус, счётчик растёт.
  Формулировки «код написан», «работает корректно» запрещены.
- Задачи на «отрефакторить потом» и «добавить тесты позже» не создаются.
