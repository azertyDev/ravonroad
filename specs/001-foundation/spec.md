# 001 — Каркас: запускаемое приложение, локали в пути, дизайн-токены

## Задача

Сегодня в репозитории лежит скаффолд: `apps/web` рендерит пустой `<StrictMode />`,
`apps/api` поднимает Nest без единого модуля, `docker-compose` не существует, БД никто
не поднимает. Ни одну заявку негде принять и негде показать.

Срез делает из скаффолда **запускаемое приложение**: `docker compose up` поднимает
Postgres+PostGIS, `api` и `edge`; `api` отвечает на `/health` и `/ready`; `web`
открывается на `/uz`, переключается на `/ru` и выглядит как продукт, а не как пустая
страница. Ни одной заявки в этом срезе ещё нет — есть каркас, в который они лягут.

Срез первый, потому что все остальные начинаются с «поднять окружение» — и без общего
каркаса каждый следующий сделал бы это по-своему.

## Пользователи

Прямого пользователя у среза нет: житель, волонтёр и модератор получают от него ноль
функций. Пользователь среза — команда: разработчик, которому нужен воспроизводимый
локальный запуск, и CI, которому нужны образы и проверки.

Косвенно срез затрагивает **жителя** через US-015: локаль по умолчанию `uz`, обе локали
с префиксом в URL.

## Сценарии

1. Разработчик клонирует репозиторий, копирует `.env.example` в `.env`, выполняет
   `docker compose up` → поднимаются `db`, `api`, `edge`; `curl localhost/api/health`
   отвечает `200`.
2. Разработчик выполняет `pnpm dev` → Vite отдаёт `web` на 5173, запросы `/api/*`
   проксируются в `api`.
3. Житель открывает `/` → редирект на `/uz/`; страница на узбекском, шапка с
   переключателем языка, подвал с контактом кампании.
4. Житель переключает язык → та же страница на `/ru/` со всеми search-параметрами.
5. Житель открывает `/xx/whatever` → редирект на `/uz/`, а не белый экран.
6. БД остановлена → `/ready` отвечает `503 {"db":"down"}`, `/health` продолжает отвечать
   `200`.
7. Разработчик пушит ветку → CI гоняет lint, typecheck и тесты; при мерже в `dev`
   собираются образы и публикуются в GHCR.

## Acceptance criteria

**AC-1 — окружение поднимается одной командой**
- Given чистый клон и заполненный `.env`,
  When выполняется `docker compose up`,
  Then поднимаются три контейнера, `curl -f localhost/api/health` возвращает `200`,
  а `curl localhost/` возвращает `index.html`.

**AC-2 — readiness отражает состояние БД**
- Given приложение запущено,
  When контейнер `db` остановлен,
  Then `/ready` отвечает `503` с телом `{"db":"down"}`, а `/health` продолжает отвечать
  `200`.

**AC-3 — локаль в пути**
- Given житель открыл `/`,
  When произошёл переход,
  Then он оказался на `/uz/`, и атрибут `<html lang>` равен `uz` (US-015).
- Given житель на `/ru/reports?status=NEW`,
  When он переключил язык,
  Then он на `/uz/reports?status=NEW` — путь и search-параметры сохранены.
- Given житель открыл `/de/`,
  When маршрут не разобран,
  Then происходит редирект на `/uz/`, а не показывается ошибка.

**AC-4 — словари не расходятся**
- Given словари локалей `uz` и `ru`,
  When выполняется `pnpm test`,
  Then тест на равенство множеств ключей проходит (SRS §11.2).

**AC-5 — статус различим без цвета**
- Given семь статусов из глоссария,
  When элемент статуса отрисован в чёрно-белом режиме,
  Then каждый статус имеет собственную форму: кольцо, ромб, штриховка, галочка, крест,
  два квадрата, косая черта (PRD §8.2).

**AC-6 — шрифты локальные**
- Given страница открыта,
  When вкладка «Сеть» отфильтрована по внешним хостам,
  Then запросов за шрифтами наружу нет: Noto Sans и IBM Plex Mono отдаются с собственного
  домена.

**AC-7 — разделитель разрядов**
- Given число 10 000,
  When оно отформатировано функцией форматирования,
  Then между разрядами стоит U+00A0, а не U+2009 (в IBM Plex Mono тонкого пробела нет).

**AC-8 — заголовки безопасности**
- Given любой ответ `edge`,
  When он получен,
  Then присутствуют `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`,
  `Strict-Transport-Security`, `Content-Security-Policy` (SRS §9.8).

**AC-9 — контракт статусов переименован**
- Given `packages/shared-types`,
  When выполняется `grep -r REQUEST_STATUSES`,
  Then совпадений нет; экспортируются `REPORT_STATUSES` и `ReportStatus`
  (преамбула SRS).

**AC-10 — CI гейтит ветку**
- Given PR в `dev` с ошибкой типизации,
  When CI отработал,
  Then проверка красная и мерж заблокирован.

## Вне рамок

- Любые заявки: таблица `report`, форма, карта, счётчик — 002 и 003.
- Полные словари локалей и аудит WCAG — 005. Здесь только каркас i18n и токены.
- `/health/details`, структурные логи, correlation id через `AsyncLocalStorage`,
  алерты — 006. Здесь только `/health`, `/ready` и middleware, проставляющий
  `X-Request-Id`.
- Telegram: ни модуля, ни таблиц, ни webhook — 004.
- S3: клиента нет, переменные в `.env.example` объявлены, но никем не читаются — 002.
- Прод-развёртывание на VPS AHOST и GCE: образы собираются и публикуются, но выкладку
  на конкретные хосты этот срез не делает.

## Требует решения продакта / владельца репозитория

1. **Тестовый раннер.** `CLAUDE.md` объявляет его невыбранным, SRS §11 рекомендует Vitest.
   Задача T-003 добавляет devDependency — требуется явное согласование, иначе ни одно
   «Готово когда» с тестом не проверяемо.
2. **Артефакт дизайн-системы.** Дизайн-система объявлена готовой (7 статусов = цвет +
   форма, Noto Sans + IBM Plex Mono), но её значения — палитра, шкала размеров, радиусы —
   в репозитории отсутствуют. Нужен файл или ссылка; выдумывать hex-значения задача
   T-014 не будет.
3. **Домены и TLS.** Имя домена прода, dev-хост, способ выпуска сертификата. Без них
   `edge` конфигурируется только под localhost.
4. **SRS §16 п.7 — архитектура VPS AHOST** (amd64/arm64): от неё зависит наличие
   prebuilt-бинарей `sharp`, а значит форма Dockerfile.
5. **SRS §16 п.14 — точный перечень доменов Яндекс JS API v3** для CSP. До ответа
   `script-src`/`connect-src` пишутся по SRS §9.8 и уточняются в 003.

## Критерии готовности среза

- `docker compose up` на чистой машине даёт отвечающий `/health` и открывающийся сайт.
- Сайт открывается на `/uz`, переключается на `/ru`, выглядит как продукт на ширине
  360 px.
- `pnpm lint`, `pnpm typecheck`, `pnpm test` зелёные локально и в CI.
- Образы `api` и `web` лежат в GHCR и запускаются из образа, а не из исходников.
- Ни один следующий срез не начинается с настройки окружения.
