# 005 — Полные локали и доступность WCAG 2.2 AA

## Задача

К концу 004 петля работает, но интерфейс дописан наполовину. Строки добавлялись
по мере надобности каждым срезом, и часть из них существует только на одном языке.
Доменные значения — статусы, причины отказа, причины «не по силам», названия районов,
категории — приходят с сервера кодами, и словарь на них никто целиком не проверял.
Доступность проверялась точечно, а не как требование.

Срез закрывает обе дыры разом: **все** строки на `uz` и `ru`, включая доменные;
интерфейс проходит WCAG 2.2 уровня AA. Обе задачи — про одно и то же: продукт,
которым можно пользоваться на своём языке и своим способом ввода.

Срез пятый, потому что проверять полноту словаря имеет смысл, когда экраны перестали
появляться, — а не после каждого нового.

## Пользователи

- **Житель** — узбекоязычный по умолчанию; интерфейс на латинице. Читает статусы,
  причины отказа и названия районов, а не только подписи кнопок (US-015).
- **Житель с ограничениями** — клавиатурный ввод, скринридер, экран при ярком солнце
  у бордюра. Форма и карта обязаны работать без мыши и без опоры на цвет.
- **Координатор** — читает те же экраны, пересылает ссылки в группу.

## Сценарии

1. Житель открывает `/uz/reports?status=OUT_OF_SCOPE` → все статусы, категории, причины
   и названия районов на узбекском; ни одного русского или английского слова.
2. Житель переключает на `/ru` → та же страница, те же фильтры, всё переведено.
3. Модератор указал причину «другое» с текстом → текст показывается как введён,
   без перевода, и рядом об этом написано.
4. Бригада добавила новую категорию `INSERT`-ом в БД → она появилась в форме на обоих
   языках без передеплоя фронта.
5. Житель проходит форму целиком с клавиатуры → фокус виден на каждом шаге, порядок
   совпадает с визуальным, координаты выбираются без перетаскивания.
6. Скринридер читает ошибку поля → сообщение связано с полем программно, а не только
   цветом рамки.
7. Житель на монохромном экране видит семь статусов → различает их по форме и подписи.
8. Житель открывает сайт в старом браузере → видит сообщение о неподдерживаемом
   браузере, а не молча сломанную страницу.
9. Житель снял фото на iPhone → оно прошло форму до конца.

## Ссылки на требования

| Источник | Что покрывается |
| --- | --- |
| PRD US-015 | Локали целиком: статусы, категории, причины отказа, названия районов |
| PRD §8.2 | WCAG 2.2 AA: контраст, размер целей 24×24, клавиатура, подписи, альтернатива перетаскиванию, список как альтернатива карте, статусы не только цветом, `<html lang>` |
| PRD §8.3 | Ширина 360 px как исходная |
| PRD §8.5 | Safari iOS обязателен, проверка на HEIC; сообщение о неподдерживаемом браузере |

| SRS §2.5 | Переводы категорий живут в БД — единственное осознанное исключение |

## Acceptance criteria

**AC-1 — словари полны и не расходятся** (US-015, SRS §11.2)
- Given словари `uz` и `ru`,
  When выполняется `pnpm test`,
  Then множества ключей совпадают, и тест падает при добавлении ключа в один словарь.
- Given union `ErrorCode`,
  When добавлен новый код без строки локали,
  Then `pnpm typecheck` красный.

**AC-2 — доменные значения переведены** (US-015)
- Given интерфейс на узбекском,
  When отрисованы статусы, категории, причины отказа, причины «не по силам» и названия
  районов,
  Then переведены они, а не только подписи кнопок.
- Given названия районов,
  When они показаны,
  Then они совпадают со свойствами `data/geo/tashkent-districts.geojson` и таблицей
  глоссария, включая `ʻ` (U+02BB) и `ʼ` (U+02BC).

**AC-3 — свободный текст модератора не переводится**
- Given причина «другое» с текстом от модератора,
  When житель открыл `/z/<token>` в любой локали,
  Then текст показан как введён, и рядом написано, что это комментарий модератора.

**AC-4 — категории приходят из БД**
- Given в таблицу `category` добавлена строка,
  When житель открыл форму,
  Then новая категория видна на обоих языках без пересборки и передеплоя фронта.

**AC-5 — контраст и размер целей** (PRD §8.2)
- Given палитра дизайн-токенов,
  When выполняется проверка контраста,
  Then текст и значимые элементы дают не ниже 4,5:1, крупный текст — не ниже 3:1.
- Given любой интерактивный элемент,
  When измерена его целевая область,
  Then она не меньше 24×24 CSS-пикселей.

**AC-6 — клавиатура и фокус** (PRD §8.2)
- Given форма подачи заявки,
  When она проходится только с клавиатуры,
  Then достижимы все поля, включая выбор координат; фокус виден; порядок фокуса
  совпадает с визуальным.
- Given фильтры и карта,
  When они проходятся с клавиатуры,
  Then фильтр применяется и сбрасывается без мыши.

**AC-7 — ошибки связаны с полями** (PRD §8.2, US-006)
- Given поле с ошибкой,
  When ошибка показана,
  Then она связана с полем программно (`aria-describedby`), а не только цветом,
  и у каждого поля есть связанная подпись.

**AC-8 — статус читается без цвета** (PRD §8.2)
- Given семь статусов,
  When страница отрисована в монохроме,
  Then каждый различим по форме и подписи: кольцо, ромб, штриховка, галочка, крест,
  два квадрата, косая черта.

**AC-9 — язык страницы** (US-015, PRD §8.2)
- Given локаль в пути,
  When страница отрисована,
  Then `<html lang>` совпадает с ней и меняется при переключении.
- Given житель переключил язык на любой странице,
  When переход выполнен,
  Then открыта та же страница во второй локали со всеми search-параметрами.

**AC-10 — Safari iOS и HEIC** (PRD §8.5, SRS §16 п.3)
- Given реальный iPhone (не симулятор),
  When житель выбрал фото из галереи и отправил заявку,
  Then заявка создана, предпросмотр показан в правильной ориентации, а результат
  проверки внесён в SRS §16 п.3.

**AC-11 — неподдерживаемый браузер** (PRD §8.5)
- Given браузер вне списка поддержки,
  When открыта любая страница,
  Then показано сообщение о неподдерживаемом браузере, а страница не ломается молча.

## Вне рамок

- Третья локаль. Локалей две, `uz` и `ru` (`CLAUDE.md`); английский в интерфейс
  не выводится.
- Перевод серверных сообщений. `message` в ответе об ошибке — для разработчика,
  на английском, в UI не показывается никогда (SRS §8.1).
- Перевод текстов Telegram-бота на две локали: группа волонтёров говорит на одном
  языке, и PRD этого не требует.
- Скриншотные тесты визуальных регрессий: требуют инфраструктуры и постоянного
  обновления эталонов, при трёх экранах дешевле посмотреть глазами (SRS §11.5).
- Полный аудит внешним специалистом и сертификация: срез закрывает требования
  PRD §8.2, а не формальную аттестацию.

## Требует решения продакта

1. **Кто вычитывает узбекские формулировки.** Глоссарий даёт термины, но не тексты
   интерфейса целиком. Нужен носитель языка на вычитку — иначе перевод будет
   «технически полным» и нечитаемым.
2. **SRS §16 п.3 — HEIC на iOS Safari.** Отдаёт ли `input[type=file]` исходный HEIC
   или уже конвертированный JPEG. Проверяется на реальном устройстве; от ответа
   зависит, нужен ли текст ошибки про формат вообще.
3. **PRD §12.10 — подсказка о приватности в поле «ориентир».** Текст публичен, житель
   может написать номер своей квартиры. Нужна ли подсказка в интерфейсе или проверка
   модератором.
4. **PRD §12.9 — текст на маркере `OUT_OF_SCOPE`.** Не читается ли реестр как обещание
   ремонта. Если нужен явный текст — он появляется здесь, вместе со словарями.
5. **Список поддерживаемых браузеров на дату релиза** (PRD §8.5): «две последние
   мажорные версии» нужно превратить в конкретный список для сообщения и для CI.

## Критерии готовности среза

- Ни одного непереведённого слова при обходе всех экранов на обеих локалях.
- Тест равенства ключей и тест полноты словаря кодов ошибок зелёные.
- Форма, фильтры и карта проходятся с клавиатуры от начала до конца.
- Проверка контраста по палитре зелёная; целевые области не меньше 24×24.
- Заявка с реального iPhone доходит до конца, результат по HEIC записан в SRS §16.
- Статусы различимы в монохроме.
