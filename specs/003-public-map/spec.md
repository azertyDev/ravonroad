# 003 — Публичная карта, список, карточка, счётчик и страница отслеживания

## Задача

После 002 заявки есть в базе, но увидеть их нельзя. Житель, отправивший заявку,
не знает, дошла ли она; сосед не знает, что на его яму уже заявили; координатор не может
собрать выезд; кампания не может показать, что она работает.

Срез открывает всё публичное чтение: карту с кластерами, список с фильтрами в URL,
карточку заявки, счётчик отремонтированного и страницу `/z/<token>`, на которой
заявитель видит судьбу своей заявки и может удалить контакты.

Срез третий, потому что читать имеет смысл только после того, как есть что читать,
и потому что **чтение — это то, что примет удар анонса**: десятки тысяч сессий
запрашивают одно и то же (SRS §1.6). Кэш здесь не оптимизация, а условие работы.

## Пользователи

- **Житель** — карта, список, карточка, счётчик, `/z/<token>`.
- **Координатор** — тот же публичный интерфейс: срез по району и статусу, ссылка
  на него в группу как план выезда. Отдельного интерфейса в MVP нет и не будет
  (PRD §2.4).
- Посторонний — публичный реестр `OUT_OF_SCOPE` без авторизации и без обращения
  к команде (BRD §7).

## Сценарии

1. Житель открывает главную → карта Ташкента с кластерами и счётчик отремонтированного.
2. Житель нажимает «моё местоположение» → карта центрируется; отказ в доступе не
   показывается как сбой.
3. Житель тапает кластер → зум до уровня, на котором кластер распадается; тапает
   одиночный маркер → всплывающая карточка с первым фото, статусом, районом и ссылкой.
4. Координатор выбирает «район = Чиланзарский, статус = `ACCEPTED`» → список и карта
   показывают тот же набор; он копирует URL и кидает в группу.
5. Житель открывает свою `/uz/z/<token>` → статус, история переходов с датами, его фото;
   для `DONE` — фото «после» и ссылка на публикацию; для `REJECTED` — причина в его
   локали; для `DUPLICATE` — ссылка на оригинал.
6. Житель нажимает «удалить мои контакты» → телефон и ник исчезают немедленно,
   заявка и фото остаются.
7. Кто-то открывает прямую ссылку на `REJECTED`-заявку → «заявка не опубликована»
   без раскрытия содержимого.
8. Анонс: десятки тысяч заходов в час → до `api` доходит один запрос карты в 30 секунд,
   остальное отдаёт `edge`.

## Acceptance criteria

**AC-1 — карта и кластеры** (US-001)
- Given карта загрузилась,
  When она отрисована,
  Then на ней маркеры всех публичных заявок (PRD §6.1), сгруппированные в кластеры.
- Given в радиусе 40 экранных пикселей больше одного маркера,
  When карта отрисована,
  Then они объединены в кластер с числом заявок внутри.
- Given житель тапнул кластер,
  When карта перестроилась,
  Then масштаб увеличен до уровня, на котором кластер распадается.
- Given в видимой области больше 5000 точек,
  When ответ получен,
  Then он несёт `truncated: true`, и UI показывает «приблизьте карту, показаны не все».

**AC-2 — геопозиция без сбоев** (US-002)
- Given житель отказал в доступе к геопозиции,
  When карта отрисована,
  Then она открыта на границах Ташкента целиком, и показана подсказка про пин,
  а не сообщение об ошибке.
- Given позиция жителя вне 12 полигонов,
  When позиция получена,
  Then карта остаётся на Ташкенте и показывает, что кампания работает только в Ташкенте.

**AC-3 — фильтры адресуемы** (US-003, US-031, US-033)
- Given выбраны статусы, категории, район и диапазон дат,
  When фильтр применён,
  Then параметры отражены в search-строке URL.
- Given такой URL открыт в новой вкладке,
  When страница загрузилась,
  Then фильтры восстановлены полностью, и список с картой показывают тот же набор.
- Given житель нажал «назад»,
  When состояние вернулось,
  Then действует предыдущий набор фильтров, а не сброшенный.
- Given фильтр не дал ни одной заявки,
  When список отрисован,
  Then показано пустое состояние с перечнем применённых фильтров и кнопкой сброса.
- Given в URL передан мусорный параметр,
  When маршрут разобран,
  Then значение отброшено, а страница не упала.

**AC-4 — карточка и приватность** (US-004, PRD §6.2)
- Given заявка публична,
  When открыта её карточка,
  Then показаны фото «до», район, категория, ориентир, дата создания, текущий статус
  и полная история переходов с датами.
- Given заявка в `DONE`,
  When карточка открыта,
  Then дополнительно показаны фото «после» и ссылка на публикацию, если она есть.
- Given у заявки есть контакт,
  When карточка открыта кем угодно,
  Then ни телефон, ни Telegram-ник не отображаются **и не приходят на клиент**.
- Given заявка в `REJECTED` или `DUPLICATE`,
  When открыта её прямая ссылка,
  Then ответ `404`, неотличимый от несуществующей заявки.

**AC-5 — счётчик считается из данных** (US-005, PRD 5.3.2)
- Given есть заявки в `DONE`,
  When открыта главная,
  Then счётчик показывает их точное число и цель 10 000, разделитель разрядов U+00A0.
- Given заявка перешла в `DUPLICATE`, `REJECTED` или `OUT_OF_SCOPE`,
  When счётчик пересчитан,
  Then значение не изменилось.

**AC-6 — страница отслеживания** (US-013)
- Given житель открыл `/z/<token>` без авторизации,
  When страница загрузилась,
  Then показаны статус, история переходов с датами, его фото «до», а для `DONE` —
  фото «после» и ссылка на публикацию.
- Given заявка в `REJECTED` или `OUT_OF_SCOPE`,
  When страница открыта,
  Then показана причина, выбранная модератором, в локали жителя.
- Given заявка в `DUPLICATE`,
  When страница открыта,
  Then показана ссылка на исходную заявку.
- Given токен неверный,
  When страница запрошена,
  Then ответ «не найдено» без различия между «не существовал» и «был удалён».

**AC-7 — удаление контактов** (US-014)
- Given житель оставлял контакт,
  When он нажал «удалить мои контакты» и подтвердил,
  Then телефон и ник удалены немедленно и безвозвратно, а заявка, фото и статус остались.
- Given контактов не было,
  When страница открыта,
  Then кнопка не показывается.
- Given удаление уже выполнялось,
  When запрос повторён,
  Then ответ `204` — операция идемпотентна.

**AC-8 — токен не утекает** (SRS §9.2)
- Given страница `/z/<token>` подключает внешние ресурсы,
  When браузер их запрашивает,
  Then заголовок `Referer` не отправляется: `Referrer-Policy: no-referrer` на всём сайте.
- Given ответ `/api/track/*`,
  When он получен,
  Then на нём `Cache-Control: no-store`, и токена нет ни в логах, ни в метриках.

**AC-9 — чтение под массовым заходом** ⚡ (SRS §4.7)
- Given два запроса `/api/reports/map` подряд в пределах 30 секунд,
  When второй обработан,
  Then он обслужен кэшем: до `api` он не дошёл (`X-Cache-Status: HIT`).
- Given TTL кэша истёк под нагрузкой,
  When пришла сотня одновременных запросов,
  Then к `api` ушёл один (`proxy_cache_lock`), остальным отдан просроченный ответ.
- Given БД недоступна и кэш пуст,
  When запрошена карта,
  Then ответ `503`, а не пустой массив: пустая карта и сломанная карта обязаны
  различаться.

**AC-10 — пагинация устойчива** (SRS §4.3)
- Given между запросами первой и второй страницы созданы новые заявки,
  When получена вторая страница,
  Then в ней нет ни дублей, ни пропусков относительно первой.
- Given передан битый курсор,
  When запрос обработан,
  Then ответ `400 INVALID_CURSOR`, а не молчаливый сброс на первую страницу.

## Вне рамок

- Смена статусов и всё, что связано с Telegram, — 004. Здесь заявки только читаются,
  и в MVP их статус меняется лишь ботом.
- Полные словари локалей и аудит WCAG — 005. Строки появляются по мере надобности,
  полнота проверяется там.
- Машинная выгрузка среза в CSV/GeoJSON — v1.1 и v2 (PRD §11). US-033 закрывается
  срезом в интерфейсе, файла не будет.
- Серверная агрегация кластеров по сетке. Порог перехода — ~10⁵ точек (SRS §3.4),
  цель кампании — 10 000; до него клиентская кластеризация работает без оговорок.
- Метрики, алерты и структурные логи — 006.

## Требует решения продакта

1. **PRD §12.9 — `OUT_OF_SCOPE` на публичной карте.** Реестр публичен по BRD §7,
   но заявитель, чья яма помечена «не по силам», видит её на карте наравне с рабочими.
   Не читается ли это как обещание ремонта? Нужен ли явный текст на маркере
   и в карточке. Срез ставит отдельный маркер реестра (PRD §6.1) — текст остаётся
   за продуктом.
2. **SRS §16 п.2 — `YMapClusterer`** в актуальной версии Яндекс JS API v3: наличие
   и API. Блокирует T-053.
3. **SRS §16 п.1** — условия использования тайлов и JS API для некоммерческой
   кампании. Блокирует публичный запуск карты, не разработку.
4. **SRS §16 п.14** — точный перечень доменов JS API для CSP. Уточняется по консоли
   браузера в этом срезе; правка — одна строка nginx.
5. **Playwright как зависимость** (SRS §11.4). Три E2E-сценария объявлены обязательными;
   раннер требует согласования, как и Vitest в 001.
6. **Стартовое наполнение карты.** Пустая карта в день запуска — продуктовый вопрос:
   показываем ли что-то, кроме нулевого счётчика. В PRD ответа нет.

## Критерии готовности среза

- Главная открывается с картой и счётчиком; кластеры распадаются по тапу.
- Ссылка на срез «район + статус» открывается у другого человека тем же набором.
- Карточка `REJECTED`-заявки отвечает «не опубликована», а `OUT_OF_SCOPE` видна
  с отдельным маркером.
- `/z/<token>` показывает историю и причину; кнопка удаления контактов работает
  и идемпотентна.
- Второй запрос карты в пределах 30 секунд не доходит до `api`.
- Ни один публичный ответ не содержит контактов, токена, IP и сигналов антиабуза —
  это проверяется тестом на форму ответа, а не глазами.
