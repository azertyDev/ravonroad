# Состав модераторов

Allowlist живёт **таблицей `moderator`**, а не переменной окружения (ADR-0005). Отсюда
главное свойство: состав меняется без передеплоя и без изменения кода (US-024). Кнопки
в карточке видит вся группа — право менять статус даёт только строка в этой таблице,
и сверка идёт на сервере до любой записи (SRS §6.2).

## Первичный засев

`TELEGRAM_MODERATOR_IDS` — список `telegram_user_id` через запятую. Он читается **только**
при старте `api` и вставляет недостающие строки (`ON CONFLICT DO NOTHING`), поэтому:

- удаление идентификатора из переменной **не** снимает полномочия;
- повторный запуск ничего не дублирует;
- мусор в переменной пропускается молча — лишняя запятая не оставит кампанию без API.

Дальше переменная не нужна. Она источник первого состава, а не источник истины.

## Как узнать `telegram_user_id`

Попросить человека нажать любую кнопку в карточке. Нажатие вне allowlist отклоняется,
но пишется в лог событием `unauthorized_button_press` вместе с `telegramUserId`:

```sh
docker compose logs api | grep unauthorized_button_press
```

## Добавить модератора

```sql
INSERT INTO moderator (telegram_user_id, display_name, added_by_moderator_id)
VALUES (123456789, 'Азиз', (SELECT id FROM moderator WHERE telegram_user_id = 987654321));
```

`added_by_moderator_id` — кто выдал полномочия; `NULL` только у засеянных при первом
развёртывании. `display_name` показывается в карточке строкой «кто поставил статус»
и публично не публикуется никогда (PRD §6.2).

## Снять полномочия

```sql
UPDATE moderator
   SET is_active = false, deactivated_at = now()
 WHERE telegram_user_id = 123456789;
```

**Только так, не `DELETE`.** На `moderator.id` ссылается каждая строка
`report_status_history`, и удаление либо не пройдёт по внешнему ключу, либо потребует
обнулить авторство прошлых решений — то есть стереть аудит.

Изменение действует с первого же нажатия: allowlist читается на каждый `callback_query`,
кэша у него нет.

## Вернуть полномочия

```sql
UPDATE moderator SET is_active = true, deactivated_at = NULL WHERE telegram_user_id = 123456789;
```

## Посмотреть состав

```sql
SELECT telegram_user_id, display_name, is_active, added_at, deactivated_at
  FROM moderator ORDER BY added_at;
```

Команд бота `/mod_add`, `/mod_del`, `/mod_list` в MVP нет: они появятся, когда состав
бригады начнёт меняться чаще раза в месяц (SRS §2.8). Потолок решения известен — правка
требует доступа к серверу, поэтому владелец доступа должен быть тем же человеком, что
и координатор кампании.

## Что allowlist не закрывает

Фотографии «после» принимает **любой** участник группы, не только модератор (PRD §12.4).
Решение принято осознанно: требование быть модератором остановило бы закрытие заявок
в поле. Риск закрывается закрытостью группы — вступление по приглашению координатора.

По той же причине кнопку «Отменить» может нажать автор перехода, даже если он не
модератор: заявку в `DONE` переводит волонтёр, и отменить свою ошибку в течение
15 минут должен он же (SRS §6.10).
